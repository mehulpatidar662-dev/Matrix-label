## API wiring (lib/api.ts)
- apiFetch<T>(path, init): same-origin, JSON, parses the error envelope and throws ApiError. Generate types from apps/api/openapi.json when it exists (openapi-typescript); otherwise hand-write them from AGENTS.md.
- Register → POST /v1/auth/register; login → POST /v1/auth/login; on success go to /dashboard. Map invalid_credentials to "Invalid email or password", email_taken to "An account with this email already exists", and validation_error details to the matching fields. Both Google buttons are plain links to /v1/auth/google/start. "Forgot password?" opens a small dialog → POST /v1/auth/forgot-password and always shows "If that email exists, we've sent a reset link."
- Stats strip → GET /v1/public/stats on mount (format labels_delivered as "10M+", avg_delivered_iou to 2 decimals, spot_check_pct as "5%", first_sample_turnaround_hours as "48h"); the count-up animates to the fetched values. Fallback = the static values in the spec.
- Estimator → POST /v1/quotes/estimate (debounced 250 ms, abort stale requests) and render from the response. Fallback = lib/pricing.ts implementing the pricing rules from AGENTS.md; a Vitest test proves it matches docs/pricing-fixtures.json (create the file from AGENTS.md if missing).
- "Talk to us →" opens a dialog (name, email, company, message) → POST /v1/leads {source: "enterprise"}; success state "Thanks — we'll be in touch."
- Footer status → GET /v1/status: green dot "All systems operational", amber "Degraded performance", grey "Status unavailable" on failure (show "All systems operational" while loading).
- /dashboard: a minimal card "You're signed in as {name} ({role}). Your dashboard is coming next." with a Log out button (POST /v1/auth/logout → /). If GET /v1/auth/me returns 401, redirect to /login.
- NEXT_PUBLIC_USE_MOCKS=true swaps in in-memory fakes for every call (any valid email + password ≥ 8 chars signs in) so the site can be demoed without the API.
